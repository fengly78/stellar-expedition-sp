## 2. 战斗引擎：我们比预想的好（纠正上次审计的误判）

上次全量审计里我写过"防御高阶性价比下降""战斗无 seed"。对照 Rust 引擎后需要修正一个印象：**我们的 `battle.ts` 与 OGameX 的 Rust 引擎是算法同构的**，不是"残缺实现"。

| 机制 | OGameX（Rust） | 我们（battle.ts） | 结论 |
|---|---|---|---|
| 回合上限 | `for _ in 0..6` | `for (let i=0; i<6; i++)` | 一致 |
| 目标选择 | `rng.gen_range(0..len)` 纯随机 | 纯随机 | 一致 |
| 弹开阈值 | `damage < 0.01 × 原始护盾` | `damage < 0.01 * target.spec.shield` | 一致 |
| 概率爆炸 | `hull/max < 0.7` → 概率 `1 - ratio` | 同 | 一致 |
| 护盾每回合回满 | `current_shield = shield_points` | `u.shield = u.spec.shield` | 一致 |
| rapidfire 概率 | `100 - 100/amount` | `1 - 1/rf` | 一致 |
| 防御无 rapidfire | 是（`DefenseObjects` 无该字段） | 是（`rapidfire: {}`） | 一致 |
| 随机源 | `thread_rng()`，**无 seed** | `Math.random()`，**无 seed** | 同样缺陷 |

**"无 seed"这一条 OGameX 也没解决**——他们的解法不是 seed，而是**战斗在服务端一次性结算后落库**，刷新页面只重放录像、不重算。这对我们单机项目有直接参考价值：与其给前端加 PRNG，不如把 `BattleOutput` 写进存档，刷新只读结果。这条路比 seed 化简单，也堵死了"刷新重开"的口子。

真正的差距不在算法，在**数据表**（§3）。

## 3. 已落地：rapidfire 表补全 + 轰炸机护盾修复

### 3.1 查出的两个确凿问题

**① rapidfire 表只有 6 条关系，严重稀疏。** 对照 `MilitaryShipObjects.php`，缺失的关键项包括：巡洋舰→火箭发射器 `rf=10`（早期唯一能压制火箭海的克制关系）、全部舰种→太阳能卫星 `rf=5`、死星的整套碾压表。

### 3.4 一条必须诚实说明的结论

rapidfire 补全**没有**扭转"防御堆叠在防守战中的优势"：同价火箭海仍然打崩巡洋舰和轰炸机。

这是 OGame 的**既定设计**（防守方有地利），不是我们的 bug。上次审计提出的高阶防御性价比问题需要另解——`doc/numbers-audit-2026-09-19.md` 的 C2（让防御占用建筑空间，使空间效率取代资源效率成为约束）仍然是最优雅的那个方案。**rapidfire 解决的是"舰种选择毫无意义"，不是"防御太强"。**

## 4. 能源公式：找到了标准答案

这是本次最有决策价值的发现，直接回答了上一轮悬置的问题。

**OGameX 的做法——发电与耗电走同一管道、同一量纲：**

```
产量：metal 30×L×1.1^L | crystal 20×L×1.1^L | deut 10×L×1.1^L×(1.44-0.004×temp)
耗电：金属矿 10×L×1.1^L | 晶体矿 10×L×1.1^L | 重氢合成器 20×L×1.1^L
发电：太阳能电站 20×L×1.1^L
减产：floor(发电/耗电 × 100) → clamp(0,100) → 产量 × 该百分比
```

三个要点：**(a) 发电与耗电用同一个 `L×1.1^L` 骨架，只有系数不同；(b) 都不额外乘速度常量；(c) 连续比例，下限 0，无 0.2 保底。**

对照我们：`solarOutput` 乘了 `SPEED=4`，`energyConsumption` 没乘。三矿同级时耗电 40 单位、发电 20×4=80 单位 → **供需比恒为 2.00，减产机制从未真正生效**（与上一轮诊断一致）。参考实现同样条件下是 20/40 = **0.50**。

**修正后玩家需要电站比矿井高 4–5 级才不减产**（解 `20×E×1.1^E = 40×L×1.1^L`：L=10 → E≈13.8；L=20 → E≈25）。这与 OGame 玩家的实际体验一致：电站必须一直跟着矿走。

三个选项（维持上一轮的排序，现已有权威依据支撑）：

| 选项 | 做法 | 结果 | 存档冲击 |
|---|---|---|---|
| A 维持 | 不动 | 机制继续失效 | 无 |
| B **推荐** | 去掉发电的 SPEED **且**电站基数 20→40 | 同级 ratio = 1.0，**跟上就不减产、落后才被罚** | **无** |
| C 严格对齐 | 只去掉发电的 SPEED | 同级 ratio = 0.5，需高 4–5 级 | **所有存档当场减产 50%** |

推荐 B 的理由：既让机制真正生效（落后就被罚），又不惩罚现有玩家——你已经在抱怨产能低了，C 会雪上加霜。基数 40 可以自圆其说为"快速宇宙的双倍发电设定"。

**另一个可调项**：我们的减产有 0.2 保底，参考实现下限是 0（完全没电就归零）。0.2 保底更宽容，建议保留——单机游戏没必要这么硬。

## 5. 可借鉴的中后期设计（我们最缺的部分）

我们已确认的问题是"Lv.20 左右玩家会觉得没得玩"。OGameX 里有三个正对此症的系统：

### 5.1 角色职业（CharacterClassService）—— 最推荐

三职业互斥覆盖三条成长线，加成表（代码实测值）：

| | Collector 采集者 | General 将军 | Discoverer 发现者 |
|---|---|---|---|
| 产量 | 矿产 **×1.25**、能量 ×1.10 | — | — |
| 军事 | 运输船速 ×2 | 战舰速 ×2、**氘耗 ×0.5**、战斗科技 **+2**、舰队栏 **+2** | — |
| 探索 | — | — | **研究时间 ×0.75**、远征收益 ×1.5、远征次数 +2、**遇敌概率 ×0.5**、不活跃掠夺 75%（默认 50%） |
| 加速折扣 | 建筑 ×0.9 | 船厂 ×0.9 | 研究 ×0.9 |

**设计精髓不在数值，在切换成本**：首次免费，之后昂贵（他们用 50 万暗物质），且有舰队在外时禁止切换 → 制造"路线承诺"。我们单机无暗物质，可换成"清空在外舰队 + 一笔重氢 + 24 小时冷却"，同样成立。这是纯单机可实现的，且能给中期玩家一个明确的自我定位。

### 5.2 远征任务（ExpeditionMission）—— 补 Lv.20 空窗

结果权重表（归一化后近似概率）：资源 **35** / 空手 **25** / 舰船 **17** / 延时 7.5 / 暗物质 7.5 / 海盗战 3.0 / 加速返航 2.75 / 外星人战 1.5 / 商人 0.4 / **黑洞全灭 0.2**。

奖励先掷稀有度：**普通 89% (×1) / 稀有 10% (×2–3) / 异常 1% (×5–10)** —— 标准的高方差可重复内容。

**单机化改造点**：(a) 资源上限按"全服第一名积分"分档 → 改为按玩家自身历史最高积分；(b) 商人交易、物品两项依赖玩家间市场，直接删，权重并入资源/舰船；(c) 海盗/外星人遭遇战用"玩家舰队造价 × 百分比 ± 3 科技等级"自适应，**不依赖真人玩家**，可原样搬。

### 5.3 残骸场 / 太空船坞（WreckField）—— 把损失变成资产

与"打完变资源要派回收船拉"的 DebrisField 不同，WreckField 是**船壳**：被毁舰船的 31.5%–39.2% 进入残骸场（系数随太空船坞 Lv1→Lv15 递增但边际递减），**免费按时间修复**，时长 `sqrt(数量×30)×10` 秒，上限 12 小时。

价值在于给中期玩家一个"打输了也有产出"的循环，且太空船坞本身成为新的长线消费池。生成门槛：损失 ≥15 万资源且被毁舰队价值占比 ≥5%。

### 5.4 HalvingService（顺带发现）

名字像"舰队减半"，实际是**花暗物质把队列剩余时间砍半**：`ceil(剩余分钟/30 × 750)`，下限 750，上限建筑 72,000 / 研究 108,000，每条目限用一次。对我们是可选的资源 sink。
