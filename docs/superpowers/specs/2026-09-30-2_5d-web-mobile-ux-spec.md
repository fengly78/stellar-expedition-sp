# Stellar Expedition 2.5D Web / Mobile UX 规格

> 状态：v0.1 设计基线  
> 日期：2026-09-30

## 1. UX 目标

将经典表格式太空策略改造成“可视化帝国控制台”，但不牺牲高频操作效率。

核心原则：
- 场景负责理解；
- 面板负责决策；
- 队列负责时间；
- 地图负责空间；
- 报告负责解释。

## 2. 视觉方向

推荐：
- 2.5D isometric / 轻透视；
- 深色太空背景；
- 高对比 HUD；
- 建筑采用模块化工业科幻；
- 不做纯写实 3D；
- 不要求持续高 GPU 占用；
- 动画服务于状态表达而非装饰。

Web 端目标 60fps 常规交互；低端移动设备允许降级动画。

## 3. 主导航

一级入口：
- 星球
- 建设
- 科研
- 船坞
- 防御
- 舰队
- 星系
- 战报
- 市场
- 联盟
- AI 总督
- 任务/成就

桌面端采用固定侧栏或图标轨道；移动端采用底部主导航 + More 抽屉。

## 4. 全局 HUD

始终可见：
- 当前星球；
- 金属；
- 晶体；
- 重氢；
- 能源；
- 建造状态；
- 研究状态；
- 舰队状态；
- 告警。

资源变化需提供：
- 当前值；
- 每小时净增；
- 仓容；
- 达上限预计时间。

## 5. 星球 2.5D 基地

中央主场景为可缩放星球基地。

### 5.1 分区
- 资源工业区；
- 能源区；
- 科研区；
- 船坞/轨道区；
- 防御区；
- 行政/贸易区。

### 5.2 建筑交互
点击建筑：
1. 聚焦；
2. 右侧打开详情；
3. 显示当前等级；
4. 下一等级效果；
5. 资源成本；
6. 时间；
7. 前置条件；
8. 升级按钮。

长按/右键：
- 收藏；
- 查看科技依赖；
- 设置 AI 管理；
- 打开历史。

## 6. 建筑升级动画

不需要完整施工模拟，采用状态分层：
- idle；
- constructing；
- upgrading；
- damaged；
- low-power；
- boosted。

升级完成时场景模型发生明显但克制的视觉变化。

## 7. 建造/研究队列

底部统一 Timeline：
- 建筑；
- 研究；
- 制造；
- 舰队；
- AI 任务。

桌面可展开为横向时间轴；移动端为可上拉 Bottom Sheet。

每个任务显示：
- 图标；
- 名称；
- 预计完成；
- 剩余时间；
- 依赖；
- 可取消/不可取消状态。

## 8. 星系地图

星系地图是核心交互，不做普通表格。

### 8.1 视觉
- 中央恒星；
- 轨道环；
- 行星/废墟/舰队/事件节点；
- 缩放层级；
- 威胁颜色和图标；
- 侦察等级覆盖层。

### 8.2 操作
点目标后展示 Action Ring：
- 侦察；
- 运输；
- 攻击；
- 回收；
- 殖民；
- 查看情报；
- 联盟标记。

拖拽地图不触发命令，避免误操作。

## 9. 舰队编成器

采用左右两栏：

左侧：
- 可用舰船；
- 数量；
- 舰种筛选。

右侧：
- 当前舰队；
- 货舱；
- 速度；
- 燃料；
- 预计航时；
- 风险提示。

底部：
- 任务；
- 姿态；
- 目标；
- 出发。

高级玩家可保存 Fleet Preset。

## 10. 战斗回放

战报默认先显示摘要，不强迫看动画。

回放模式：
- 2.5D 舰队阵型；
- 时间轴；
- 每轮伤害；
- 关键技能/速射提示；
- 可暂停；
- 1x/2x/4x；
- 直接跳结果。

移动端允许切换为“轻量时间轴”以减少性能负担。

## 11. AI 总督界面

AI 不是聊天框优先，而是“策略控制台”。

页面包括：
- 当前托管状态；
- 今日执行动作；
- 风险等级；
- 预算；
- 自动化规则；
- 禁止事项；
- 上次总结；
- 需要玩家决定的问题。

自然语言可以用来解释和调整建议，但真正生效的权限必须转成结构化 Policy 并让玩家确认。

## 12. 告警系统

告警分级：
- INFO：任务完成、资源临界；
- NOTICE：侦察完成、市场订单；
- WARNING：可疑舰队、能源不足；
- CRITICAL：确定来袭、关键设施受损。

不得把所有通知都做成红色。

移动端关键告警支持系统推送，前提是用户授权。

## 13. 新手引导

不采用 30 步强制遮罩教程。

改为“目标驱动”：
1. 升级金属矿；
2. 建能源；
3. 开科研；
4. 造侦察单位；
5. 查看星系；
6. 完成第一次侦察；
7. 完成第一次 PvE 任务；
8. 解锁 AI 总督。

每个目标都解释“为什么”，而不是只指按钮。

## 14. 桌面布局

目标 1440×900：
- 左：主导航；
- 上：资源 HUD；
- 中：2.5D 场景；
- 右：上下文详情；
- 下：队列/时间线。

支持 1920×1080 扩展信息密度。

## 15. 移动端布局

目标宽度 360–430px：
- 顶部：简化资源条；
- 中央：场景；
- 底部：5 个主导航入口；
- 详情使用 Bottom Sheet；
- 复杂表格转换为卡片；
- 关键操作在拇指热区。

不把桌面三栏简单缩小到手机。

## 16. 响应式降级

低性能设备：
- 关闭粒子；
- 降低阴影；
- 减少背景舰船；
- 战斗默认轻量回放；
- 建筑动画降低帧率；
- 仍保留完整功能。

## 17. 可访问性

必须支持：
- 键盘导航；
- 可读焦点状态；
- 文本缩放；
- 图标配标签；
- 重要状态不只依赖颜色；
- 动画减少选项；
- 屏幕阅读器可访问关键表单和战报摘要。

## 18. UI 状态规范

每个数据区域必须有：
- loading；
- empty；
- error；
- stale；
- offline；
- success。

服务器拒绝命令时必须解释：
- 缺什么资源；
- 哪个前置条件未满足；
- 是否可重试；
- 是否状态已变化。

## 19. 性能预算

首屏目标：
- 静态资源按路由拆包；
- 场景资产懒加载；
- 首屏不加载完整战斗资产；
- 同屏建筑实例采用复用；
- 不因为 HUD 更新导致整个场景重渲染。

## 20. 组件边界

建议 React 组件层级：
- AppShell
- ResourceDock
- PlanetScene
- ContextPanel
- QueueTimeline
- GalaxyScene
- FleetComposer
- CombatReplay
- AutopilotConsole
- NotificationCenter

业务状态通过 API snapshot + domain store 管理，渲染状态与服务器权威状态分离。

## 21. 动画语义

动画只表达：
- 建造；
- 资源流；
- 舰队移动；
- 受击；
- 告警；
- 状态完成；
- 选中/聚焦。

禁止使用影响操作判断的大面积无意义循环动画。

## 22. MVP 页面

首批必须完成：
1. 登录/进入宇宙
2. 星球总览
3. 建设
4. 科研
5. 船坞
6. 防御
7. 舰队编成
8. 星系地图
9. 战报
10. AI 总督
11. 设置

市场和联盟可作为下一阶段，但导航位置先保留。

## 23. 验收标准

- 桌面与移动都能完成建设、研究、造船、派舰、侦察、战报完整流程。
- 新玩家无需阅读外部教程即可完成第一次星系任务。
- 任何危险命令都有明确确认与后果提示。
- 从收到来袭告警到设置撤退策略，移动端不超过 4 个主要交互步骤。
- AI 托管动作可在 UI 中完整追溯。
