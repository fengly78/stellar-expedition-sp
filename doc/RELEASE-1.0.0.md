# 星际远征 SP v1.0.0 发布说明

- 版本：v1.0.0
- 发布日期：2026-09-29
- 代码基线：公开仓库的首个根提交；旧本地开发历史未公开。
- 分发形态：纯前端静态站点（单机）+ 可选的服务端多人模式（`game-server/`，PHP + SQLite/MariaDB）
- 许可：MIT，见根目录 `LICENSE`。

## 一句话

OGame 式太空策略游戏，浏览器直接打开即玩（单机），也可连服务端多人对战。
无遥测、无广告、零默认数据上报。

## 功能范围

**经济**：13 类行星设施 + 6 类月面设施；金属/晶体/重氢三资源；电力供需与减产机制；仓满丢弃；矿脉储量。
**服务端**：账号自助注册、Bearer 令牌、命令信封（唯一资产变更入口）、
建造/研究/造船/舰队全链路、战斗结算与战报、GM 后台与审计。

**军事**：15 种舰船、10 种防御设施；速射表；残骸回收；星际导弹；战斗回放。

**探索**：星系扫描、间谍、远征、殖民、月球开发。

**其它**：15 步新手教程、成就、军官、指挥官、战役关卡（含精英）、排行榜、术语图鉴。

**技术**：零依赖语言包（zh/en）、PWA 离线可玩、Service Worker autoUpdate、存档 v2→v11 迁移链。

## 基线变更记录

`tag v1.0.0` 初版指向 `8efe3b0`（17 项修复）。此后经两轮验证又修 **28 项**，tag 已重指向。
全部修复均带防回归门禁，且**每条都做过变异验证**（改回缺陷形态确认门禁转红）。

### 第二轮：前端存档 / 经济 / i18n（11 项）

- **资源入账超仓静默销毁**（高）——战利品、运输卸货、取消退款的 11 条路径是裸 `+=`，
  不封顶，而 `produce()` 每 tick 用 `Math.min` 把超出部分抹掉。Lv0 仓的殖民地卸载
  27,500 金属 → 实得 10,000，**17,500 凭空蒸发且无任何提示**。其中**交易最严重**：
  收益被削为 0 而付出已真实扣除，玩家净损失。现全部收口到单一真值源，
  「仓容是硬上限」的平衡口径原样保留，只把销毁时点从暗处搬到明处并如实上报。
- **存档入口结构校验缺失**（2 高）——导入不校验 `planets` 是不是数组，
  任意垃圾 JSON 会被写入槽位并提示「导入成功」，**直接覆盖正常存档且不可恢复**；
  版本闸对 `saveVersion` 缺失失效，导致缺版本的档被放行、9 级迁移全跳过，
  **进入游戏后首个 tick 即抛且每 tick 都抛**。另有配额满时谎报保存成功、
  云端恢复无 try/catch 致按钮永久 disabled。
- **EN 侧中文残留清零**（中）——`state.ts` 50 处 toast 硬编码中文、
  星球名未走翻译、数据结构缺 En 字段、全角标点漏进 EN 输出。
- **隐私声明屏把 EN 用户困住**（中）——正文是中文字面量，
  而未同意前 `App.tsx` 只渲染这一屏、语言切换器在其后。

### 第三轮：服务端（真实三人对抗试玩暴露，12 项）

三个子智能体分饰 ALPHA / BRAVO / DELTA 在**真实服务端**上打了三场对抗，
攻守双方各自独立取证。核心修复：

- **被袭方战报失明**（高）——战报按发起方归因，被打的人永远查不到自己的战报。
  改为按 `participants_json` 的参与方匹配，并标注 `perspective` / `kind`。
- **被袭方零通知**（高）——战报、事件表、outbox 全空，只能靠轮询 state 做 diff
  才察觉被打。新增 `player.raid_inbound` 入站事件。
- **建造队列死锁**（高）——队首付不起就永久报废且不可自愈（一名 agent 实测需 181 小时）。
  新增 `BUILD_CANCEL`、入队校验建筑 id、拒绝同名重复、`BUILD_START` 跳过付不起的队首。
- **产出未接入 worker**（阻断）——`settle()` 只被 5 个命令处理器顺带调用，
  玩家一旦闲置产出恒为 0。新增 `game:process-production`。
- **掠夺账本单边**（高）——只记攻方流水却盖上守方 `planet_id`。
  改为双边记账，攻方入账为正、守方出账为负。
- **幂等重放返回体自相矛盾**（中）——重放被拒命令得到
  「外层 committed + 内层 rejected」，与同一 id 的读面端点对不上。
- **API 错误路径 500 + 调试页**（高）——不带 `Accept` 头时走 HTML 错误渲染，
  而该路径依赖一个**从未建表**的 `sessions`，本该 422 变成 500 并吐出堆栈。
- **残骸回收闭环**——原先「只写不收」，残骸永久搁置；现已按货舱等比采集（与前端同口径）。
- **RC1 冻结纪律首次有代码强制**——`config_validate.py` 此前只算 hash 从不比对，
  而 `meta.hash` 在**全部 3 个历史提交里从未一致过**。现改为比对
  「去掉 `meta.hash` 后的内容哈希」（该字段在被哈希文档内部，拿整文件哈希比
  数学上永不相等），并回填了正确值——**只改 1 行，参数与公式一字未动**。
- **PHP 括号闸扫到生成物**——会扫进 Laravel 编译后的 Blade 缓存。
  这不只是误报：生成物碰巧配平就会给出一道**永远绿的假门禁**。
  已收敛到 137 个手写文件。

## 已知限制

- **单机**：无联盟、无 ACS、无贸易商/Dark Matter。定位为个人单机版。
- **无 CI**：门禁需本地手动跑。
- **离线更新检查**：未配置 `VITE_VERSION_MANIFEST_URL` 时不检查更新（隐私声明要求，需玩家主动点击才发请求）。
- **无真机设备证据**：Edge/Chrome 正式浏览器的 24 张双语截图 + 390px 复查尚未完成，清单见 `doc/release-walkthrough-1.0.0.md`。
- **Rust 语料闸当前不可运行（环境问题，非代码缺陷）**：`cargo.exe` 被本机应用控制策略拦截
  （`应用程序控制策略已阻止此文件`，os error 4551），`rustc.exe` 本身正常。影响范围有限——
  战斗语料一致性另有 Python（`check_combat_corpus.py`）与 TS（`battle-properties` /
  `battleSim`）两道独立覆盖，Rust 那道是第三实现的交叉对拍。恢复需解除对本机
  `<CARGO_HOME>\bin\cargo.exe` 的策略封锁。

## 如何运行

```bash
cd web
npm install
npm run build        # 产物在 web/dist
npx vite preview     # 或任意静态服务器托管 dist/，需 SPA fallback
```

浏览器打开后：接受隐私声明 → 创建指挥官档案 → 开始游戏。

## 数据与隐私

全部进度、账号档案与设置仅保存在浏览器 localStorage，不上传任何服务器。不内置统计、遥测、广告或错误上报。清除站点数据即删除全部游戏数据。版本清单 URL 可选配置，仅在你主动点击检查更新时发起一次请求。
