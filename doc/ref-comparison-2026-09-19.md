# 参考实现对照分析：ogame-vue-ts

- **日期**：2026-09-19
- **参考对象**：<https://github.com/setube/ogame-vue-ts>（Vue 3 + TS + Pinia，220+ commits，v1.6.5）
- **目的**：对照成熟同类实现，找出本项目可借鉴的机制与公式缺陷
- **方法**：抓取其 `src/logic/*` 与 `doc/ogame-reference.md` 源码/文档，逐项与本项目 `web/src/game/*` 比对

## 0. 一句话结论

数值骨架我们是对的（位置系数与参考实现**完全一致**），真正该补的是三件事：**研究时间公式**（已修）、**能源量纲不一致**（待拍板）、**矿脉系统**（缺失的长期机制）。其余大面积照搬不划算。

## 2. 已落地：研究时间公式（明确 bug）

**原实现**（`objects.ts:331`）用**基础成本**算时间，漏了 `factor^level`：

```ts
return (t.cost.metal + t.cost.crystal) / SPEED / (1 + labLevel)
```

后果是荒谬的——等级越高时间越短，因为实验室等级涨得比成本快：

| 武器技术 | 研究成本 | 改前耗时 | 改后耗时 | 改后 @4x |
|---|---|---|---|---|
| Lv.5 | 2.56e4 | 36 秒 | 6.9 分 | 1.7 分 |
| Lv.10 | 8.19e5 | 21 秒 | 11.4 分 | 2.9 分 |
| Lv.15 | 2.62e7 | 15 秒 | 22.8 分 | 5.7 分 |
| **Lv.20** | **8.39e8** | **11 秒** | **49.8 分** | 12.5 分 |
| Lv.25 | 2.68e10 | **9 秒** | 1.9 时 | 28.7 分 |

注意改前 Lv.20（11 秒）比 Lv.5（36 秒）还快——**时间维度在科技线上完全消失**。

**新实现**采用参考实现的 `cost^0.3` 软化方案：

```ts
const f = Math.pow(t.factor, currentLevel)
const sum = (m*f)^0.3 + (c*f)^0.3 + (d*f)^0.3
return max(5, floor(sum / 0.003 / SPEED / ((1 + labLevel) * (1 + energyTech * 0.05))))
```

选 0.3 而非直接乘 `factor^L` 的理由：成本增长被压到 0.3 次方，终局仍可完成（Lv.25 在 4x 下 28.7 分钟），不会变成"研究一年"。下限 5 秒避免 0 秒排队。

顺带让**能源技术（113）**有了第二重意义——每级 -5% 研究时间，Lv.20 时把 11.4 分压到 5.7 分。此前它只有"太阳能 +5%/级"和当前置两个用途。

**改动文件**：`objects.ts`（公式）、`state.ts:1236`、`Research.tsx:41`、`DetailDialog.tsx:113`（同步新签名）。

## 3. 建议采纳：矿脉系统（缺失的长期机制）

这是我们与参考实现**最大的结构差距**。他们用"资源存量"而非"成本曲线"来约束深挖：

```ts
初始储量：metal   = 5e9 × posMUL.metal     × (1 + (galaxy-1)×0.05)
衰减：remaining = current / initialBase
      remaining >= 0.05 → 效率 1.0
      current   <= 0    → 效率 0.2（保底）
      否则 0.2 + 0.8 × (remaining / 0.05)     // 线性衰减
恢复：regen = 增强储量 × 0.01 × hours × (1 + 地质研究站 × 0.1)
      上限 = 增强储量 × 100%（约 100 小时回满）
上限加成：(1 + 深层钻探 × 0.2) × (1 + 采矿科技 × 0.15)
```

**为什么值得做**：我上一轮审计发现"深挖矿产边际崩塌"（矿 Lv.30 回本 25 天、Lv.40 回本 2.25 年），当时的结论是"靠成本曲线惩罚玩家、方向对但压错了对象"。矿脉提供了**另一种解法**——不靠回本周期惩罚，而靠"这颗星球有挖完的一天"。它天然导向"开殖民地"这个我们想要的行为，而且给了中期一个明确的、可读的进度条（还剩多少矿），比"回本 604 小时"直观得多。

**代价**：新增 `deposits` 状态字段、UI（警告/耗尽提示）、存档迁移 v10→v11、新的建筑（地质研究站/深层钻探设施）。这是**一个完整特性，不是调参**。

**建议**：不要现在做。先把 §4 的能源决策和战斗 seed 化收尾，再评估是否要引入这套系统。

## 4. 待拍板：能源量纲不一致

参考实现的发电与耗电**都不乘速度常量**，两边同量纲。我们是**发电乘了 SPEED=4、耗电没乘**，等于供需比被凭空放大 4 倍——这正是"矿与电站同级时 ratio 恒为 2.00、减产机制从未生效"的根因。

修正方向明确（让耗电也乘 SPEED，等价于两边都不乘），但**修正后同级立刻变成 ratio = 0.50，所有现有存档当场减产一半**。参考实现的同级宽松度是 1.43（发电 50 vs 三矿耗电 35），要达到同等体感需要把太阳能电站基数从 20 提到约 57。

选项：
- **A 维持现状**：不折腾，但能源系统继续形同虚设
- **B 修正量纲 + 提基数**：恢复张力，需要一次存档兼容处理
- **C 只提基数不动量纲**：折中，但治标不治本

**仍未擅自改动。**

## 5. 不建议照搬的部分

- **暗物质（第四资源）**：牵动采集船、专属军官、储罐、消耗场景，是半个游戏的工作量，当前三资源体系还远未打磨完
- **产量曲线 1.1 → 1.5**：我们没有矿脉约束兜底，直接换会让通胀失控。要换必须配套矿脉系统
- **二值能源开关**：他们的"不够就归零"比我们的渐进 ratio 粗暴，玩家体验更差。这条**我们更好，别抄**
- **战斗模块**：参考实现同样无 seed、同样有防御修复无门槛的 bug、rapidfire 配了没用。这块他们不比我们强，没有可抄的
